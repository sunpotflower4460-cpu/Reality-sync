# RealitySync (リアリティ・シンク)

## 概要

RealitySyncは、「理想のスケジュール」と「現実の行動・体調」のギャップを記録・可視化し、自分にとって本当に無理のない生活リズムを見つけるためのスケジューリングアプリです。

予定通りにいかなかったことを「失敗」として裁くのではなく、次の計画を現実に近づけるための観測データとして扱います。

## 現在実装されている主要機能

### 1. 日付ごとの理想スケジュール

- 前日 / 翌日へ移動
- 任意の日付を選択
- 今日へ戻る
- 日ごとに独立した予定を保存
- 予定の追加 / 編集 / 削除
- 開始時刻、予定時間、カテゴリ、想定負荷を設定
- 前日の予定をコピー
- 平日 / 休日 / 制作日など、1日の予定を名前付きテンプレートとして保存・再利用

前日コピーとテンプレートには計画データだけを使い、過去の実績・気分・実負荷・理由・実開始日時はコピーしません。

### 2. 理想と現実のデュアル・トラッキング

各予定に対して、次の現実データを明示的に記録できます。

- 予定通り / 別の活動へ変更 / スキップ
- **実際に開始した日付**
- **実際に開始した時刻**
- 実際に費やした時間
- 実負荷
- 終了時の気分
- 変更 / スキップした理由（任意）

開始時刻が分からない場合は空欄のまま保存できます。開始日時を記録した場合は、`23:50予定 → 翌日00:10開始`のような深夜跨ぎも日付込みで正確に扱います。

旧バージョンで「開始時刻だけ」が保存されていた記録については、開始日を推測で補完しません。開始日は不明の旧記録として保持します。

新しく実績を初回保存する時には、**その瞬間の予定時刻・予定名・予定カテゴリ・予定時間・想定負荷を `plannedSnapshot` として固定**します。以後、予定を編集しても当時の理想側と実績側の両方を履歴として保持できます。

古い実績に `plannedSnapshot` がない場合、現在の予定から過去の計画を推測してスナップショットを作ることはしません。

### 3. 日次ギャップ分析

- 想定負荷と実負荷の波を可視化
- 理想時間と現実時間をカテゴリ別に比較
- 予定通り / 変更 / スキップ / 未記録の件数を可視化
- 予定外に積み上がった実際の活動も表示
- 実開始日時がある場合、現実の負荷を本当の時間位置へ配置
- 翌日開始なら翌日の時間軸まで伸ばして表示
- 開始時刻なし / 開始日不明 / 日次グラフの表示範囲外の実績は、予定時刻へ推測配置せず除外件数を明示
- 記録済み予定では `plannedSnapshot` があれば記録時の計画を理想側に使用

### 4. 週間レビュー

分析タブの「週」では、選択日を含む月曜〜日曜を集計します。

- 週全体の記録率
- 記録済みの中での予定通り率
- 理想時間と現実時間の週合計
- 予定開始日時と実開始日時の平均ズレ / 平均絶対ズレ
- 曜日ごとの記録率、理想時間、現実時間、開始ズレ
- カテゴリ別の理想時間 vs 現実時間
- 変更 / スキップ理由の頻度
- 予定通り / 変更 / スキップごとの平均実負荷
- 終了時の気分件数
- 前週 / 翌週への移動

1週間だけを見て「月曜日は苦手」といった恒常的な曜日傾向は断定しません。

### 5. 月間レビュー

分析タブの「月」では選択日を含むカレンダー月を集計します。

- 月全体の記録率 / 予定通り率
- 月間の理想時間 / 現実時間
- 開始日時ズレの月間平均
- 月内の週ごとの理想時間 / 現実時間 / 記録率
- 同じ曜日を複数回まとめた曜日別の観測
- 曜日ごとの予定通り率、現実時間、開始ズレ、サンプル数
- カテゴリ別の月間 理想 vs 現実
- 月間の変更 / スキップ理由ランキング
- 前月 / 翌月への移動

曜日別画面にはサンプル数を併記します。複数回の観測があっても「曜日が原因」とは判断せず、まず記述的な比較として表示します。

### 6. バックアップ / 復元

ヘッダーの設定から、RealitySyncのローカルデータを1つのJSONとして書き出し・復元できます。

バックアップ対象:

- 日ごとの予定と実績
- 記録時の予定スナップショット
- 実開始日時・実時間・負荷・気分・理由
- 保存済みテンプレート
- リマインダー設定

復元時はバックアップ識別子・バックアップ版・予定保存版を検証し、既存の正規化処理を通してからstateを置き換えます。未知の将来版を現在版として解釈して上書きしません。

**バックアップJSONは暗号化していません。** 予定、気分、理由など個人的な記録を含むため、共有ストレージへ置く場合はファイルの扱いに注意してください。

### 7. 記録リマインダー

今日の予定が「未記録」のまま、設定した猶予時間を過ぎると記録タブに「記録待ち」として表示します。

- 今日の予定だけが対象
- 記録済み / スキップ済みは対象外
- 0 / 5 / 10 / 15 / 30 / 60 / 120分の猶予を選択
- OS通知はユーザーが明示的に許可した場合のみ利用
- 同じ予定のOS通知は同じ日に重複しないよう抑制

アプリ内の記録待ちはアプリが動作している時に確実に判定できます。OS通知もアプリ起動中・再表示時には利用できますが、現在はPushサーバーやOSネイティブのスケジューラーを持っていないため、**アプリを完全に閉じた状態で指定時刻に必ず通知することは保証しません。**

### 8. PWA基盤

- Web App Manifest
- Service Worker
- スタンドアロン表示
- 対応ブラウザのインストールプロンプト
- GitHub Pagesなどサブパス型の静的ホストを考慮した相対asset base
- 同一オリジンの読み込み済みassetをruntime cache
- 通知クリック時にRealitySyncへ戻る処理

PWAはprogressive enhancementです。初回アクセスや未キャッシュassetを含む状態での完全オフライン動作までは現段階で保証していません。

### 9. 観測インサイト候補

分析タブの **「傾向」** では、選択日までの直近180日を対象に、断定ではなく「次に確かめる価値がある候補」を生成します。

現在スクリーニングする候補:

- 曜日別の変更 / スキップ率
- 曜日別の「20分以上の開始遅れ」率
- 計画時の想定負荷70以上 vs 70未満の変更 / スキップ率
- 予定カテゴリ別の変更 / スキップ率
- 繰り返し入力された変更 / スキップ理由

候補カードは **観測事実 → サンプル数 → 差 → 95% Wilson区間 → 観測信頼度 → 仮説 → 注意点** の順で表示します。

重要な境界:

- 比較群4件未満 / 対照群8件未満は率比較候補にしない
- 15ポイント未満の差は候補に昇格させない
- `plannedSnapshot` が必要な比較では、古いスナップショットなし実績を除外
- 95% Wilson区間を表示しても「統計的有意差」とは呼ばない
- 曜日やカテゴリを複数同時探索するため、多重比較による偶然の差が混ざり得ることを明示
- 「探索中 / 反復観測 / 比較的安定した観測」は、サンプル数・複数月への反復・差の大きさ・区間分離を使った製品上の証拠レベルであり、因果確率ではない

習慣シナジーの自動断定はまだ解放していません。前後関係や反復、交絡条件を扱える段階までデータモデルを進めてから実装します。

## RealitySyncのデータ原則

RealitySyncでは、予定を使って「現実」や「過去の計画」を作りません。

- 未記録の実時間を予定時間で補完しない
- 未記録の開始時刻を予定時刻で補完しない
- 開始時刻だけの旧記録へ開始日を推測で付けない
- 古い実績へ現在の予定から `plannedSnapshot` を捏造しない
- 少数の曜日サンプルから恒常傾向を断定しない
- 負荷・気分・変更理由の同時発生を、そのまま因果関係として扱わない
- 未記録予定を「実行した」とリマインダーが推定しない
- 率の区間推定をそのまま因果・有意差の証明として扱わない

**実際の行動・時間・開始日時・気分・負荷・理由は、明示的な記録がある場合だけ現実として扱います。過去の理想側も、記録時に明示保存されたスナップショットがある場合だけ高度な縦断分析へ使います。**

## 使い方

1. ヘッダーの日付ナビゲーションで記録したい日を選びます。
2. **計画**タブで予定を作るか、前日の予定 / 保存済みテンプレートを利用します。
3. 必要に応じて予定カードを編集または削除します。
4. **記録**タブで実際の行動・開始日・開始時刻・実時間・負荷・気分・理由を記録します。
5. **分析**タブの「日 / 週 / 月」で異なる時間スケールから理想と現実を比較し、「傾向」で複数月の候補を確認します。
6. 設定からリマインダー、バックアップ、対応端末でのPWAインストールを管理します。

日別データ、テンプレート、リマインダー設定はブラウザの `localStorage` に保存されます。

### 旧デモ版からの移行

旧 `v1` 保存データにユーザーが実際に記録した変更がある場合は、初回起動日のデータとして現在の複数日形式へ移行します。

旧デモを一度も触っていない初期サンプルデータは製品データへ持ち込みません。

旧実績に記録時予定スナップショットがない場合、その過去計画は不明として残ります。現在の予定を過去の計画だったことにはしません。

## 起動方法

```bash
npm ci
npm run dev
```

本番ビルドとロジックテスト:

```bash
npm run build
npm test
```

Service Worker / インストール挙動は `localhost` または HTTPS 配信で確認してください。

## 技術構成

- React 19
- Vite 8
- Tailwind CSS 4
- Lucide React
- Node.js built-in test runner
- versioned localStorage day persistence (`reality-sync:days:v2`)
- reusable template persistence (`reality-sync:templates:v1`)
- reminder preference persistence (`reality-sync:reminders:v1`)
- versioned RealitySync JSON backup (`reality-sync-backup` v1)
- immutable optional `plannedSnapshot` on newly recorded reality
- pure daily / weekly / monthly / longitudinal candidate analytics
- local-calendar date arithmetic that avoids UTC date-key shifts
- Wilson score intervals for descriptive rate uncertainty
- Web App Manifest + Service Worker PWA foundation
